# git_auto_pull: историческая утилита

На рабочем VPS заменена Woodpecker и отдельными механизмами деплоя.
Не включать её параллельно новой системе. Точная серверная версия от 2026-10-05
сохранена в `historical/`; она содержит старые ограничения и не устанавливается.

## Установка и удаление
Требуются Linux, Python 3, Git, systemd, sudo (для смены пользователя).
`sudo sh install.sh` из любого каталога устанавливает в /usr/local/bin,
сохраняет существующую конфигурацию и оставляет расписание выключенным.
Старое cron-расписание этой утилиты удаляется с резервной копией.
Старый /usr/bin/git_auto_pull.sh при установке сохраняется: внешние ссылки надо проверить отдельно.
Makefile вызывает тот же установщик. .env больше не используется.
На Devuan эти systemd-установщики не применять: это исторический компонент VPS.

Только при осознанном возвращении старой системы: настроить /etc/git_auto_pull.conf,
затем `sudo systemctl enable --now git_auto_pull.timer`.
Удаление: `sudo sh uninstall.sh`; с конфигурацией: `sudo sh uninstall.sh --purge`.
Удаление сохраняет копии в /var/backups, не удаляет пользователя git, репозитории,
логи, sudoers или Git daemon. Общий cron не перезапускается.

## Поведение
Единая блокировка /run/lock/git_auto_pull.lock; повторный запуск пропускается.
Git-команды ограничены 180 секундами; ввод паролей отключён.
Ошибки отдельных репозиториев не мешают проверке остальных, итоговый код — 1.
Вывод идёт в stdout/stderr (journal при запуске службой).
`--config` и `--lock` позволяют изолированные проверки без /etc и /run.

Секции [var] и [projects] совместимы со старым форматом. USER принимается как
устаревший вариант GIT_USER, но системная переменная USER не меняется.
Значения читаются как данные, без shell expansion и исполнения .env.
Проверяются текущая ветка, чистота tracked/untracked файлов, возможность
fast-forward. Локальные коммиты и расхождения не сбрасываются.
Hooks отключены; RUN_HOOKS=1 явно возвращает прежнее поведение.
Внимание: ненулевой код post-merge не гарантирует неуспех Git merge;
этот режим не является проверенным деплоем. Блокировка не защищает от ручного Git.
Никакие прежние sudoers-разрешения автоматически не выдаются.

--msg и старый --telegram отправляют через включённые каналы. Поддержаны
SEND_TELEGRAM/BOT_TOKEN/CHAT_ID, SEND_SIGNAL/SIGNAL_SENDER/SIGNAL_RECIPIENT,
SEND_XMPP/XMPP_RECIPIENT (один адрес). Уведомления plain text, без Markdown.
Signal и XMPP требуют установленных signal-cli/sendxmpp и их настроек.
PAM-режим сохранён; PAM_USER/PAM_SERVICE/PAM_TYPE переключают на уведомление.
Безусловный signal-cli receive удалён. Секреты не включать в Git.
Ошибка уведомления отражается в коде завершения; уже выполненный merge не откатывается.

## Проверка
`python3 -m unittest discover -s tests -v` — локальные временные Git-репозитории.
Уведомления в реальные сервисы тесты не отправляют.
